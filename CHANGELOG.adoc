= RusTTY Changelog
:toc:

This file tracks suite-level milestones. Tool-specific details live under
`docs/changelogs/`.

== Unreleased

[#suite-config-foundation]
=== Configuration foundation

* Added a dedicated RusTTY configuration crate with TOML serialization and
  import provenance support.
* Added contributor workflow files, CODEOWNERS, and issue-template guidance.
* Added branch-name enforcement and AsciiDoc policy checks to repository
  automation.

[#suite-config-cli]
=== Config CLI workflows

* Added default-path resolution, file initialization, saving, loading, and
  validation helpers for RusTTY config files.
* Added `rustty` CLI entry points for printing the default config path,
  initializing sample config files, and validating stored config.

[#suite-rusplink-cli]
=== rusplink session planning

* Added unique session-name validation so saved config lookups stay stable
  across CLI tools.
* Added `rusplink` commands for default-path discovery, session listing, and
  SSH dry-run planning from either saved sessions or direct targets.

[#suite-rusplink-ssh-transport]
=== rusplink SSH transport

* Added a reusable `rustty-transport` crate for SSH exec requests.
* Added bootstrap `rusplink` transport support for password-authenticated SSH
  command execution with explicit, unsafe host-key override handling.

[#suite-rusplink-known-hosts-shell]
=== rusplink host keys and shells

* Added a RusTTY-managed OpenSSH-style known-host store with default-path
  resolution and append-only persistence for exact host or `host:port`
  entries.
* Added `rusplink` host-key verification against stored known-host entries and
  automatic persistence for `accept_new` sessions.
* Added interactive SSH shell support with remote PTY allocation when
  `rusplink` runs without a remote command.

=== Repository bootstrap

* Established the RusTTY workspace, tool map, and shared branch policy.
* Added extensive AsciiDoc documentation for architecture, migration,
  licensing, tools, and release management.
* Added per-tool changelogs and release-note drafts intended to feed future
  build and release automation.
