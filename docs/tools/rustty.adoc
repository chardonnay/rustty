= rustty Manual
:toc:

`rustty` is the planned cross-platform GUI terminal client for RusTTY. It
replaces PuTTY's `putty` application.

== Purpose

`rustty` is intended to open interactive sessions across SSH, Telnet, Raw,
Rlogin, and Serial transports, while also acting as the launch point for saved
sessions and migration helpers.

== Planned Capability Profile

* interactive terminal sessions
* saved session launch and editing
* PuTTY session import into RusTTY-native storage
* diagnostics and event-log surfaces
* future integration with transfer and agent workflows

== Usage Model

Running `rustty` with no arguments now opens a native desktop launcher window
backed by the shared RusTTY core and shared UI layer.

The current launcher window provides:

* a saved-session browser with search and provenance display
* a real session editor that can create, update, rename, and delete saved
  RusTTY sessions directly from the GUI
* a GUI-side PuTTY session import panel for registry exports, Unix session
  files, and `sessions/` directories
* a selected-session detail pane for auth defaults, host-key policy, and
  forwarding rules
* a dedicated saved-session terminal window for SSH command execution and a
  first live PTY-backed SSH shell, including transcript history,
  host-key confirmation, and captured output
* a quick-connect draft panel that builds launch previews for ad-hoc targets
* a tool catalog for the other RusTTY binaries and their documentation paths
* config diagnostics, sample-config creation, and path copy actions
* a darker terminal-first visual style with monospace-heavy typography,
  charcoal panels, and green-accent terminal surfaces inspired by PuTTY's
  classic dark session presentation

During the bootstrap phase, `rustty` also supports printing a sample RusTTY
configuration file for schema review and repository validation.

It now also supports default-path discovery, sample-file initialization, and
stored-config validation through a small bootstrap CLI.

It also provides bootstrap migration helpers for importing exact OpenSSH-style
host-key trust and PuTTY host-key exports into RusTTY-managed `known_hosts`
storage.

It now also provides a bootstrap PuTTY session import path into RusTTY-owned
`config.toml` storage.

== Configuration and Storage

`rustty` will read imported PuTTY sessions but should save new or updated
configuration in RusTTY-owned storage.

The GUI session editor now writes real RusTTY-native session data straight to
`config.toml`, including session names, protocols, auth defaults, host-key
policy, forwarding rules, and operator notes.

The launcher-side SSH command runner and the first live interactive shell
currently reuse saved session values for
`username`, `private_key_path`, `key_passphrase_env`,
`keyboard_interactive_env`, and `password_env`. Unknown SSH host keys are
surfaced directly in the terminal window so the operator can trust once, trust
and save, or cancel before credentials are sent.

Host-key migration currently runs through `rustty --import-known-hosts` for
OpenSSH files and `rustty --import-putty-host-keys` for PuTTY exports. Both
commands report what was imported, already present, or skipped.

Session migration currently runs through `rustty --import-putty-sessions`,
which accepts PuTTY `.reg` exports, Unix session directories, or single Unix
session files and merges normalized sessions into a RusTTY config file.
The same migration flow is now also available from the launcher window through
an explicit PuTTY import panel with dry-run reporting.

== Logging and Diagnostics

The tool is expected to expose a human-readable event log and detailed
diagnostic output suitable for support and regression testing.

== Compatibility Notes

`rustty` aims for behavioral familiarity, not a pixel-for-pixel PuTTY clone.
Intentional differences must be recorded in changelogs and release notes.
The current launcher theme now intentionally leans into a darker
terminal-operator aesthetic instead of a light form-editor look.

== Examples

[source,text]
----
rustty
----

The command above opens the native RusTTY launcher window.

[source,text]
----
rustty --help
----

[source,text]
----
rustty --print-sample-config
----

[source,text]
----
rustty --show-default-config-path
----

[source,text]
----
rustty --init-config
----

[source,text]
----
rustty --validate-config
----

[source,text]
----
rustty --show-default-known-hosts-path
----

[source,text]
----
rustty --import-known-hosts ~/.ssh/known_hosts --dry-run
----

[source,text]
----
rustty --import-putty-host-keys ~/Downloads/putty-hostkeys.reg --dry-run
----

[source,text]
----
rustty --import-putty-sessions ~/.putty/sessions --dry-run
----

Within the launcher window:

. Create or edit a saved session in the session editor, or import PuTTY
  sessions into the launcher-visible config.
. Select a saved SSH session.
. Open the dedicated terminal window for that session.
. Either enter a remote command or start the interactive shell in the terminal
  window.
. Confirm the host key if RusTTY prompts for first contact.
. Review the live shell output or the transcript, plus stdout, stderr, exit
  status, and host-key source in the terminal window.

== Current Limits

The current GUI launcher is real, and it now opens a first dedicated
saved-session terminal window with a live SSH shell, but it is not yet a full
embedded terminal client. Full terminal emulation, robust ANSI/VT handling,
advanced scrollback, copy/paste behavior, and richer session lifecycle
handling are still queued in the next `rustty` milestones.

The current terminal window workflow is intentionally smaller than the full
CLI:

* it currently supports live shells and non-interactive commands for saved SSH
  sessions only
* it does not yet expose SSH-agent auth, forwarding overrides at launch time,
  or ad-hoc quick-connect execution from the GUI
* it presents a lightweight live shell buffer with basic ANSI stripping, not a
  full terminal emulator suitable for TUIs like `vim` or `top`
