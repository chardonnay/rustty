= rusplink Manual
:toc:

`rusplink` is the command-line remote execution and SSH planning client for
RusTTY. It replaces PuTTY's `plink`.

== Purpose

`rusplink` is intended for scripting, automation, remote command execution,
port forwarding, and non-GUI access to the RusTTY connection stack.

== Bootstrap Capability Profile

* default-config path discovery
* default known-hosts path discovery
* listing stored RusTTY sessions
* session-backed SSH invocation planning
* direct-target SSH invocation planning
* OpenSSH or PuTTY `PPK` private-key authentication with optional passphrase
  indirection
* SSH-agent authentication through either `SSH_AUTH_SOCK` or an explicit
  agent socket path
* keyboard-interactive authentication with environment-driven prompt responses
* password-authenticated SSH exec transport for remote commands
* local TCP port forwarding through SSH `direct-tcpip`
* remote TCP forwarding through SSH `tcpip-forward`
* dynamic SOCKS5 forwarding through SSH `direct-tcpip`
* interactive SSH shell transport with remote PTY allocation
* OpenSSH-style known-host lookup and append-only persistence
* remote-command capture after `--`
* compatibility-oriented reuse of imported PuTTY session metadata

== Planned Capability Profile

* richer host-key prompts and compatibility flows
* compatibility-oriented import of legacy PuTTY sessions
* SSH agent forwarding and non-Unix agent integrations

== Usage Model

The bootstrap CLI is already scriptable and explicit:

* `--show-default-config-path` prints RusTTY's platform-resolved config path.
* `--show-default-known-hosts-path` prints the default OpenSSH-style host-key
  store path used by RusTTY.
* `--list-sessions` prints the validated session table from a RusTTY config.
* `--session NAME --dry-run` resolves a stored SSH session into a connection
  plan.
* `TARGET --dry-run` resolves a direct SSH target into the same plan format.
* `--local-forward SOURCE=TARGET` adds a local listener that tunnels TCP
  traffic through the SSH server.
* `--remote-forward SOURCE=TARGET` adds a remote listener that tunnels TCP
  traffic back to the local RusTTY client.
* `--dynamic-forward [HOST:]PORT` adds a local SOCKS5 listener that opens SSH
  TCP tunnels on demand.
* `TARGET -- COMMAND...` or `--session NAME -- COMMAND...` executes a remote
  SSH command over the new bootstrap transport layer.
* `TARGET` or `--session NAME` without a command opens an interactive SSH shell
  with a requested remote PTY.

Live transport already supports both remote command execution and interactive
shells. Public keys, SSH-agent identities, keyboard-interactive responses, and
passwords are read through explicit CLI or session configuration, and host
keys are resolved through RusTTY's explicit known-hosts flow. Local TCP,
remote TCP, and dynamic SOCKS listeners stay active for the lifetime of the
SSH session and share the same authenticated connection.

== Configuration and Storage

`rusplink` accepts RusTTY session references through `--session` and loads them
from the default config path or an explicit `--config PATH`.

Imported PuTTY sessions remain migration inputs, not the ongoing write target,
but their provenance is surfaced in dry-run output and session listings.

Saved RusTTY SSH sessions can now also carry a preferred `username`,
`private_key_path`, `key_passphrase_env`, `keyboard_interactive_env`, and
`password_env`. `rusplink` uses those values automatically unless the caller
overrides them with `--username`, `--private-key`, `--key-passphrase-env`,
`--keyboard-interactive-env`, or `--password-env`.

Saved `private_key_path` values can reference either OpenSSH private keys or
PuTTY `PPK` files.

Saved RusTTY sessions can also carry reusable local forwarding rules through
`port_forwards`. CLI-provided `--local-forward` values are appended to those
saved rules for the current invocation.

Saved RusTTY sessions can also carry reusable remote forwarding rules through
`remote_forwards`. CLI-provided `--remote-forward` values are appended to
those saved rules for the current invocation.

Saved RusTTY sessions can also carry reusable dynamic SOCKS listeners through
`dynamic_forwards`. CLI-provided `--dynamic-forward` values are appended to
those saved listeners for the current invocation.

Host keys live in a separate OpenSSH-style `known_hosts` file that defaults to
the same RusTTY-owned config base directory. `rusplink` can use the platform
default location or an explicit `--known-hosts PATH`.

== Authentication and Host Keys

The bootstrap transport currently supports four SSH auth modes:

* OpenSSH or PuTTY `PPK` private-key authentication through `--private-key PATH`
* SSH-agent authentication through `--agent` or `--agent-socket PATH`
* keyboard-interactive authentication through `--keyboard-interactive-env ENV`
* password authentication through `--password-env ENV`

If multiple auth sources are configured, `rusplink` tries public-key auth
first, then SSH-agent auth, then keyboard-interactive, then password
authentication.

* `--private-key PATH` selects the OpenSSH or PuTTY `PPK` private key to load.
* `--key-passphrase-env ENV` selects the environment variable that contains
  the private-key passphrase when the selected key is encrypted.
* `--agent` enables SSH-agent authentication through the current
  `SSH_AUTH_SOCK` environment variable.
* `--agent-socket PATH` enables SSH-agent authentication and forces the socket
  path used for identity lookup and signing requests.
* `--keyboard-interactive-env ENV` selects the environment variable that
  contains newline-separated responses for server prompts.
* `--password-env ENV` selects the environment variable that contains the SSH
  password.
* Without `--password-env`, `rusplink` reads `RUSTTY_SSH_PASSWORD` only when
  no private key, agent, or keyboard-interactive response source is
  configured.
* `--username USER` overrides the username for session-backed connections.
* Direct targets can also supply the username through `user@host`.
* Saved sessions can provide default `username`, `private_key_path`,
  `key_passphrase_env`, `keyboard_interactive_env`, and `password_env` values,
  so recurring SSH targets no longer need to repeat them on every invocation.
* `~` in private-key paths is expanded against `HOME` or `USERPROFILE` before
  the SSH transport tries to load the key.
* PuTTY `PPK` inputs are accepted anywhere `--private-key PATH` or a saved
  `private_key_path` is used, including encrypted `PPK` files when a
  passphrase environment variable is available.
* Scripted keyboard-interactive responses are consumed in prompt order, one
  line per prompt. Extra configured lines are ignored once authentication
  finishes.

Host-key handling now follows the RusTTY session policy plus the local
known-hosts file:

* `--known-hosts PATH` overrides the host-key database location for the
  current invocation.
* `strict` requires at least one exact stored key match for the resolved host
  and port.
* `ask` also accepts stored exact matches, but still errors for unknown hosts
  because interactive confirmation is not implemented yet.
* `accept_new` accepts a first-seen host key and persists it to the
  known-hosts file after a successful bootstrap session.
* `--unsafe-accept-host-key` still bypasses verification for disposable
  testing, but it does not persist trust.

The current bootstrap lookup intentionally matches exact host and `host:port`
entries that RusTTY writes itself. Wildcards, negations, markers, and hashed
hostnames are preserved on disk but are not used as trust matches yet.

On Unix-like hosts, `rusplink` can authenticate against a running `rusagent`
process or any compatible `SSH_AUTH_SOCK` endpoint. Windows-style Pageant IPC
and SSH agent forwarding are still outside the current bootstrap slice.

== Port Forwarding

The current bootstrap transport supports local TCP forwarding, remote TCP
forwarding, and dynamic SOCKS5 forwarding.

* `--local-forward SOURCE=TARGET` can be repeated.
* `SOURCE` accepts either `port` or `host:port`.
* `TARGET` must be `host:port`.
* Bare local ports bind to `127.0.0.1`.
* IPv6 hosts can be written as bracketed endpoints such as
  `[::1]:18080=[2001:db8::20]:8080`.
* `--remote-forward SOURCE=TARGET` can be repeated.
* `SOURCE` accepts either `port` or `host:port`.
* `TARGET` must be `host:port`.
* Bare remote source ports bind to `127.0.0.1` on the SSH server side.
* `--dynamic-forward [HOST:]PORT` can be repeated.
* Bare dynamic-forward ports bind to `127.0.0.1`.
* Dynamic forwarding currently supports SOCKS5 `CONNECT` requests for IPv4,
  IPv6, and DNS-style destinations.

Forwarding rules are visible in dry-run output as `port_forward_N=SOURCE->TARGET`.
Remote forwarding rules are visible in dry-run output as
`remote_forward_N=SOURCE->TARGET`.
Dynamic listeners are visible in dry-run output as
`dynamic_forward_N=LISTEN_ADDRESS`.
Saved RusTTY session forwards are merged with CLI forwards so long-lived
session definitions can keep common local tunnels, remote tunnels, and local
SOCKS listeners in one place.

== Logging and Diagnostics

The current bootstrap output is line-oriented and script-friendly. Dry-run
plans expose origin, config path, known-hosts path, host, port, command,
ordered authentication methods, private-key path, key-passphrase source,
agent socket path, keyboard-interactive response source, password source,
host-key policy, transport host-key mode, storage origin, and forwarding
metadata. Session listings now also expose stored usernames, private-key
paths, key-passphrase environment variable names, keyboard-interactive
environment variable names, password environment variable names, plus
local-forward, remote-forward, and dynamic-forward counts so operators can
review reusable auth defaults without opening the TOML file manually.

== Compatibility Notes

The current bootstrap CLI uses long-form Rust-style flags such as `--session`,
`--config`, `--known-hosts`, `--dry-run`, `--password-env`, and
`--unsafe-accept-host-key`. It does not yet provide PuTTY-compatible short
flags such as `-load`.

Any user-visible divergence from `plink` must continue to be documented in
changelogs and release notes.

== Current Limits

Current bootstrap limits include:

* only SSH sessions can be resolved by `rusplink`
* `--config` is only used for `--session` and `--list-sessions`
* dynamic forwarding currently supports SOCKS5 `CONNECT`, not `BIND` or
  `UDP ASSOCIATE`
* keyboard-interactive auth is currently environment-driven; interactive local
  challenge prompts are not implemented yet
* `ask` still lacks an interactive prompt for unknown hosts, so it requires a
  pre-trusted exact known-host entry for live execution
* known-host matching is intentionally conservative and currently ignores
  wildcard, negated, marked, or hashed host patterns
* saved sessions currently model private-key paths and environment-variable
  indirection, not direct secret storage
* writing or editing PuTTY `PPK` files is handled by `rusttygen`, not
  `rusplink`
* remote commands run through SSH `exec`; PTY-backed interactive shells are
  available only when no remote command is supplied
* direct targets support `host`, `user@host`, `host:port`, and
  `[ipv6-host]:port`, but not the full future flag surface of `plink`
