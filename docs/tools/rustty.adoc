= rustty Manual
:toc:

`rustty` is the planned cross-platform GUI terminal client for RusTTY. It
replaces PuTTY's `putty` application.

== Purpose

`rustty` is intended to open interactive sessions across SSH, Telnet, Raw,
Rlogin, and Serial transports, while also acting as the launch point for saved
sessions and migration helpers.

== Planned Capability Profile

* interactive terminal sessions
* saved session launch and editing
* PuTTY session import into RusTTY-native storage
* diagnostics and event-log surfaces
* future integration with transfer and agent workflows

== Usage Model

Running `rustty` with no arguments now opens a native desktop launcher window
backed by the shared RusTTY core and shared UI layer.

The current launcher window provides:

* a saved-session browser with search and provenance display
* a selected-session detail pane for auth defaults, host-key policy, and
  forwarding rules
* a quick-connect draft panel that builds launch previews for ad-hoc targets
* a tool catalog for the other RusTTY binaries and their documentation paths
* config diagnostics, sample-config creation, and path copy actions

During the bootstrap phase, `rustty` also supports printing a sample RusTTY
configuration file for schema review and repository validation.

It now also supports default-path discovery, sample-file initialization, and
stored-config validation through a small bootstrap CLI.

It also provides bootstrap migration helpers for importing exact OpenSSH-style
host-key trust and PuTTY host-key exports into RusTTY-managed `known_hosts`
storage.

It now also provides a bootstrap PuTTY session import path into RusTTY-owned
`config.toml` storage.

== Configuration and Storage

`rustty` will read imported PuTTY sessions but should save new or updated
configuration in RusTTY-owned storage.

The current sample config now demonstrates session-level SSH defaults such as
stored usernames and password environment variable names, so future GUI editing
work has a concrete schema target from the beginning.

Host-key migration currently runs through `rustty --import-known-hosts` for
OpenSSH files and `rustty --import-putty-host-keys` for PuTTY exports. Both
commands report what was imported, already present, or skipped.

Session migration currently runs through `rustty --import-putty-sessions`,
which accepts PuTTY `.reg` exports, Unix session directories, or single Unix
session files and merges normalized sessions into a RusTTY config file.

== Logging and Diagnostics

The tool is expected to expose a human-readable event log and detailed
diagnostic output suitable for support and regression testing.

== Compatibility Notes

`rustty` aims for behavioral familiarity, not a pixel-for-pixel PuTTY clone.
Intentional differences must be recorded in changelogs and release notes.

== Examples

[source,text]
----
rustty
----

The command above opens the native RusTTY launcher window.

[source,text]
----
rustty --help
----

[source,text]
----
rustty --print-sample-config
----

[source,text]
----
rustty --show-default-config-path
----

[source,text]
----
rustty --init-config
----

[source,text]
----
rustty --validate-config
----

[source,text]
----
rustty --show-default-known-hosts-path
----

[source,text]
----
rustty --import-known-hosts ~/.ssh/known_hosts --dry-run
----

[source,text]
----
rustty --import-putty-host-keys ~/Downloads/putty-hostkeys.reg --dry-run
----

[source,text]
----
rustty --import-putty-sessions ~/.putty/sessions --dry-run
----

== Current Limits

The current GUI launcher is real, but it is not yet a full embedded terminal
client. Interactive session windows, terminal emulation, scrollback,
copy/paste behavior, and live session lifecycle handling are still queued in
the next `rustty` milestones.
