= Configuration Model
:toc:

RusTTY stores new configuration in a RusTTY-owned format and uses PuTTY storage
only as an import source.

== Goals

* Keep the serialized schema explicit and versioned.
* Preserve session provenance for imported data.
* Keep tool metadata close to the Rust workspace so documentation and runtime
  stay aligned.
* Make it easy to print, inspect, and test sample configuration.
* Keep SSH trust state in a RusTTY-owned known-hosts file instead of relying
  on unsafe one-off overrides.

== Bootstrap Schema

The initial configuration crate models:

* a schema version,
* the product name,
* a session store with normalized sessions,
* optional per-session SSH username and password-environment defaults,
* optional import provenance for migrated sessions, and
* a per-tool profile list derived from the shared tool metadata table.

Session names are now validated as unique so CLI tools such as `rusplink` can
load them deterministically by name. Empty stored SSH usernames and empty
`password_env` names are rejected during validation so bootstrap CLIs do not
have to guess how to recover from malformed auth defaults.

== Sample Configuration

The `rustty` bootstrap binary can print a sample RusTTY TOML file:

[source,shell]
----
cargo run -p rustty -- --print-sample-config
----

This sample is intended to give future import and storage work a stable target.
It now also demonstrates how RusTTY stores reusable SSH auth defaults inside a
session definition.

== Default Config Path Policy

RusTTY resolves the default config file by platform:

* Windows: `%APPDATA%/RusTTY/config.toml`
* macOS: `~/Library/Application Support/RusTTY/config.toml`
* Unix-like systems: `$XDG_CONFIG_HOME/rustty/config.toml` when available,
  otherwise `~/.config/rustty/config.toml`

== Bootstrap CLI Operations

The current `rustty` bootstrap binary supports:

* `--print-sample-config`
* `--show-default-config-path`
* `--init-config [PATH]`
* `--validate-config [PATH]`

These flows are intentionally small but already exercise the versioned RusTTY
config schema and on-disk validation path.

The same config schema can now also be consumed by `rusplink` for session
listing and SSH dry-run planning.

== Known-Hosts Path Policy

RusTTY resolves the SSH known-hosts file in the same platform-specific base
directory as `config.toml`:

* Windows: `%APPDATA%/RusTTY/known_hosts`
* macOS: `~/Library/Application Support/RusTTY/known_hosts`
* Unix-like systems: `$XDG_CONFIG_HOME/rustty/known_hosts` when available,
  otherwise `~/.config/rustty/known_hosts`

The current bootstrap persistence intentionally appends new exact host or
`[host]:port` entries and preserves unrelated lines already present in the
file.
